# Upgrade to clean core 0.3 + private plugins

## Before changing a live installation

1. Record its exact commit, Python executable and service/launcher command. Back up config
   (including permissions), module directory/link inventory and state DB. Do not print auth
   configuration. Preserve local/foreign working-tree changes.
2. Test the candidate in a separate checkout and temporary HOME. Run full tests, `doctor`,
   and a fixture browser check. `--no-setup --no-pip` does not touch boot services or agents.
3. Review each local patch. Move private snapshot paths, registry operations, account labels
   and instance names into a private repository. Generic UI or correctness improvements belong
   in the same public core used by all installations.
4. Keep a single owner for process supervision. A plugin row should expose only actions that
   call the existing lifecycle API; do not add a competing host kill/restart path.

## Operator-controlled cutover

Use the reviewed public release/commit unchanged. Until the candidate is actually published,
the included content manifest proves candidate integrity, not parity with today's GitHub main.
Do not claim a published version that does not exist. No GitHub push is part of installation.

- Install each private plugin as its own directory/link in `modules_dir`, with a versioned
  manifest. Never replace `agentsmon/dashboard.py` or other core files with private variants.
- Retain old executable modules which collect snapshots; the corresponding API plugin can
  hide only their duplicate cards through `hidden_services`. Legacy modules elsewhere remain.
- Retain `hidden_sessions` settings and existing manual labels. Check Hermes overrides in
  `pinned_daemons`: an old autogenerated `tag` takes precedence over detection. Remove that
  field only after confirming it is an obsolete autogenerated override, not intentional branding.
- Restart **only the dashboard** in an agreed window. No agent TUI/container/bridge restart is
  needed for display migration. Existing keepalive/runtime ownership remains unchanged.
- Check `/api/state`, `doctor`, model labels, Telegram links, fixed-width layout, plugin error
  cards and action guards. Test an authorized idle reload only with the instance owner's approval.
- When uninstalling a plugin, remove its link/opt-in and restart the dashboard; do not edit core.

## Rollback

Restore the recorded dashboard launcher/checkout and config/module-link inventory, then restart
only the dashboard. Do not reset/delete agent state or recreate sessions. No destructive DB
migration is introduced here; the uptime database schema is unchanged. Keep both checkouts until
acceptance is complete. A review-stage private plugin directory can simply remain uninstalled.

## Integrity and release maintenance

`agentsmon/core-manifest.json` records every package file (excluding the manifest and Python
bytecode), version, reviewed release identifier and a SHA-256 of the canonical file-hash map.
`doctor` exits nonzero for modified/unverified core, plugin failure or missing tmux. The footer
checks content on each state response. Compare the manifest to a separately trusted release
when publisher identity matters: a same-user attacker can change both code and manifest.

Maintainer-only preparation after code review:

```bash
python3 scripts/core_manifest.py --release v0.3.0
python3 -m unittest discover -s tests -v
```

The first command prints a candidate manifest; save/review it as `agentsmon/core-manifest.json`
in the release commit and rerun tests. It never silently repairs a dirty installation. The
review-stage manifest uses `v0.3.0-review`; recording the release tag later is a reviewed change.
Packaged installs include the same manifest via package-data. Local `__pycache__` is excluded.

## Extension compatibility

API version is an integer, currently 1. A future incompatible API is rejected visibly.
Plugins must not import private core functions. Public integration points are the manifest,
JSON contract, actions and `detect.prettify_model` for display formatting. Each plugin keeps
its own version/tests; no coupling to an internal dashboard class or HTTP handler.
